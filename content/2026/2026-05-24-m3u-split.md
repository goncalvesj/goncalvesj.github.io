A while back I ended up with a single M3U playlist with thousands of entries grouped into dozens of categories, most of which I had no interest in. Loading it was slow and finding anything was painful.

So I built a small side project called m3u-split to fix it. The flow is simple: drop in an M3U file, tick the categories you want, download a trimmed playlist.

You can try it here:

**<https://goncalvesj.github.io/m3u-split/>**

And the source code is here:

**<https://github.com/goncalvesj/m3u-split>**

## What M3U files look like

An M3U entry is just two lines, a metadata line and a URL:

```text
#EXTINF:-1 tvg-id="example.1" group-title="Category A",Entry Name
http://example.com/path/123
```

The bit the app cares about is `group-title="..."`. That's how entries are bucketed, and that's the unit you select on or filter out.

## How it works

There are two steps and both are backed by regex:

- Extract categories: scan the file for every distinct `group-title` value and present them as a checklist.
- Filter by selection: keep only the `#EXTINF` lines (plus the URL line below them) that match a category you ticked.

The client-side parser is about ten lines of TypeScript:

```ts
export const extractCategories = (content: string): string[] =>
  [...new Set([...content.matchAll(/group-title="([^"]+)"/g)].map(m => m[1]))]

export const filterByCategories = (content: string, categories: string[]): string => {
  if (!categories.length) return ''
  const escaped = categories.map(c => c.replace(/[.*+?^${}()|[\]\\]/g, '\\$&')).join('|')
  return (content.match(
    new RegExp(`#EXTINF:-\\d+[^\\n]*group-title="(${escaped})"[^\\n]*\\n[^\\n]+\\n`, 'g')
  ) || []).join('')
}
```

One thing to call out: escaping the user-supplied category names before plugging them into a regex matters here. Real-world category names love their `|`, `()` and `+` characters.

## Architecture

The app supports two processing modes behind a feature flag:

- Client-side (default): the file never leaves your browser. React reads it, parses it, and serves the trimmed result back as a blob download. Good for privacy and good enough for any playlist that fits in memory.
- Server-side (optional): a .NET 9 Azure Functions API does the same work, with an option to persist uploads to Azure Blob Storage. Useful if you want to share a processed playlist or hand large files off to the backend.

On the backend, the same regex idea shows up but with modern .NET niceties like `[GeneratedRegex]` for source-generated patterns and `JsonSourceGenerationOptions` for AOT-friendly serialization:

```csharp
[GeneratedRegex(@"group-title=""([^""]*)""")]
private static partial Regex CategoryRegex();
```

## The tech stack

- Frontend: React 19, TypeScript, Vite (rolldown-vite build)
- Backend: .NET 9 Azure Functions v4 (isolated worker), Application Insights
- Storage: Azure Blob Storage (optional) or local disk
- Hosting: GitHub Pages for the client, Azure Static Web Apps for the full client + API setup

The UI itself is deliberately small. There's a dropzone, a searchable checklist with select-all and clear, a download button, and a three-step indicator across the top. No state management library, no component framework, just `useState` and a single CSS file.

## Lessons from the rewrite

The original 2021 version was an Angular app with a heavier UI. When I came back to it earlier this year I rewrote it as a small React + Vite app and the codebase got dramatically simpler. The entire parsing module is now a handful of lines and the UI is one component.

For tools like this, the smallest thing that solves the problem is usually the right thing.
